# PRD: 个人开销统计仪表盘 (Personal Expense Dashboard)

## 0. Document Purpose

本 PRD 为《未来技术》课程大作业项目的需求规格文档，是团队（一人）从需求到实现的核心参考。目标是在 1-2 小时内完成一个可运行、可演示的纯前端开销仪表盘。文档结构：Vision → User → Features → MVP Scope → Success Metrics。无既有 UX 文档，本 PRD 是唯一需求来源。

## 1. Vision

一个打开 HTML 就能用的开销可视化面板。用户录入每一笔消费后，图表即时刷新，让"钱花到哪了"不再是一个模糊的月末感受，而是一张清晰的饼图。全部数据存本地、不上传、零注册。

## 2. Target User

### 2.1 Jobs To Be Done
- Functional: 快速记录一笔开销（< 3 秒/笔）
- Functional: 一眼看到本月各类别消费占比
- Contextual: 月末复盘时知道"这个月我最贵的 3 笔是什么"
- Emotional: 缓解"钱又没了"的模糊焦虑

### 2.2 Non-Users (v1)
- 需要多设备同步的用户
- 需要预算提醒的用户
- 企业/团队共享账本需求

### 2.3 Key User Journeys

- **UJ-1. 小明录入一笔外卖开销。**
  - **Persona + context:** 大学生小明，午饭点了 35 元外卖，想记一下但不想打开记账 App。
  - **Entry state:** 浏览器打开仪表盘页面，已处于录入表单视图。
  - **Path:** (1) 金额输入框自动聚焦 → (2) 输入 35 → (3) Tab 到类别下拉框（默认选中"餐饮"）→ (4) 回车提交。
  - **Climax:** 页面右侧环形图和统计卡片自动刷新，"餐饮"占比扇形变大，本月支出 +35。
  - **Resolution:** 小明看到图表更新，关掉页面做别的；下次打开数据还在。

- **UJ-2. 小红月底复盘。**
  - **Persona + context:** 刚工作的小红，想知道这个月工资花到了哪里。
  - **Entry state:** 打开仪表盘，默认显示当月数据。
  - **Path:** (1) 查看环形图 → 发现"购物"占比 40% → (2) 切换柱状图看各月支出趋势 → (3) 滚动到列表看具体哪几笔最贵。
  - **Climax:** 小红发现"购物"里有 3 笔美妆消费共 800 元，决定下月砍掉。
  - **Resolution:** 小红点击导出 JSON 备份，关掉页面。

- **UJ-3. 小强清空重来。**
  - **Persona + context:** 小强试玩后觉得之前的录入都是测试数据，想清空。
  - **Entry state:** 打开设置区域。
  - **Path:** (1) 点击"清空所有数据" → (2) 弹窗二次确认 → (3) 确认。
  - **Climax:** 图表、列表、统计卡片全部归零。
  - **Resolution:** 小强开始正式录入。

## 3. Glossary

- **Expense（开销）** — 一条消费记录，包含金额、类别、日期、备注。
- **Category（类别）** — 开销的分类标签，预置 7 种，支持自定义。
- **Dashboard（仪表盘）** — 主视图，包含统计卡片、图表区域、列表区域。
- **Persistence（持久化）** — 数据存入浏览器 localStorage，刷新/关闭后不丢失。
- **Backup（备份）** — 将全部数据导出为 JSON 文件，或从 JSON 文件导入。

## 4. Features

### 4.1 开销录入

**Description:** 用户通过简洁表单录入一笔开销。表单字段：金额（数字，必填，> 0）、类别（下拉选择，默认选中上次使用的类别）、日期（默认今天）、备注（可选，最长 100 字）。提交后即时写入 localStorage 并刷新所有图表和列表。 realizes UJ-1。

**Functional Requirements:**

#### FR-1: 录入表单
用户可以填写金额、选择类别、设置日期、添加备注，提交后生成一条开销记录。

**Consequences (testable):**
- 金额为空或 ≤ 0 时，提交按钮禁用或弹出校验提示
- 类别默认为"餐饮"（或用户上次使用的类别）
- 日期默认为今天（YYYY-MM-DD）
- 提交后 1 秒内，所有图表和列表刷新

#### FR-2: 预置类别 + 自定义类别
系统预置 7 个常用类别（餐饮、交通、购物、娱乐、居住、医疗、其他），用户可以添加自定义类别。

**Consequences (testable):**
- 类别下拉框包含全部预置类别
- 用户输入新类别名并确认后，该类别永久加入下拉选项
- 自定义类别名不能为空或纯空格

#### FR-3: 删除开销
用户可以删除已录入的开销记录。

**Consequences (testable):**
- 列表中每条记录旁有"删除"按钮
- 删除后图表和列表即时刷新
- 删除操作不可撤销（v1 不做回收站）

### 4.2 可视化仪表盘

**Description:** 页面上半部分为仪表盘视图，包含 3 张图表和 3 张统计卡片。 realizes UJ-2。

**Functional Requirements:**

#### FR-4: 类别占比环形图
系统按类别聚合当前时间区间内的开销金额，生成环形图展示各类别占比。

**Consequences (testable):**
- 有数据时正确显示各扇形，图例标注类别和金额
- 无数据时显示空状态提示（"暂无数据，快去录入第一笔开销吧！"）
- 鼠标悬停扇形时显示详细金额

#### FR-5: 月度支出柱状图
系统按月份聚合全部历史数据，生成柱状图展示每月总支出。

**Consequences (testable):**
- 每个月份一根柱子，柱子上方标注金额
- 月份按时间顺序排列（最早 → 最新）

#### FR-6: 支出趋势折线图
系统按日期聚合当前月数据，生成折线图展示当月每日支出趋势。

**Consequences (testable):**
- X 轴为日期，Y 轴为支出金额
- 数据点用圆点标记，悬停显示具体金额

#### FR-7: 统计卡片
页面顶部显示 3 张统计卡片：总支出（全部历史）、本月支出、最高单笔。

**Consequences (testable):**
- 数字实时更新，格式化为带千分位的货币（如 ¥1,234.56）
- "最高单笔"同时显示金额和对应的类别

### 4.3 开销列表

**Description:** 页面下半部分为开销列表，按日期倒序排列，支持按类别筛选。 realizes UJ-2。

**Functional Requirements:**

#### FR-8: 开销列表展示
系统按日期倒序展示全部开销记录，每条显示：日期、类别（带颜色标签）、金额、备注（如有）、删除按钮。

**Consequences (testable):**
- 默认显示全部记录
- 超过 20 条时显示滚动区域

#### FR-9: 类别筛选
用户可以通过下拉框筛选只看某个类别的开销。

**Consequences (testable):**
- 选择类别后，列表和所有图表同步刷新为只包含该类别的数据
- "全部"选项恢复显示所有数据

### 4.4 数据持久化与备份

**Description:** 所有开销数据存入 localStorage，支持导出 JSON 备份和从 JSON 导入。 realizes UJ-2, UJ-3。

**Functional Requirements:**

#### FR-10: localStorage 持久化
系统自动将全部开销数据存入浏览器 localStorage，页面加载时自动恢复。

**Consequences (testable):**
- 刷新页面后数据完整保留
- 关闭浏览器重开后数据完整保留
- localStorage key 为 `expense_dashboard_data`

#### FR-11: JSON 导出
用户可以一键将全部开销数据导出为 JSON 文件下载。

**Consequences (testable):**
- 点击"导出"按钮后浏览器触发下载
- 文件名格式：`expense-backup-YYYY-MM-DD.json`
- JSON 结构包含版本号、导出时间、开销数组

#### FR-12: JSON 导入
用户可以从之前导出的 JSON 文件恢复数据。

**Consequences (testable):**
- 支持选择本地 JSON 文件并解析
- 导入前弹窗确认："导入将覆盖当前数据，确定继续？"
- 格式错误时显示友好错误提示

#### FR-13: 清空数据
用户可以一键清空所有开销数据。 realizes UJ-3。

**Consequences (testable):**
- 点击"清空"按钮后二次确认弹窗
- 确认后 localStorage 清空，所有图表/列表归零

## 5. Non-Goals (Explicit)

v1 明确**不做**以下功能：
- ❌ 预算设置与超支提醒
- ❌ 收入/工资管理
- ❌ 多设备同步 / 账号体系
- ❌ 移动端 App / 小程序
- ❌ 账单拍照 OCR
- ❌ 多人共享账本
- ❌ 借贷/转账记录
- ❌ Excel 导出/导入（v2 再考虑）
- ❌ 图表自定义（颜色、类型切换）

## 6. MVP Scope

### 6.1 In Scope
- 开销录入表单（金额、类别、日期、备注）
- 预置 7 类别 + 自定义类别
- 3 张图表：环形图（类别占比）、柱状图（月度）、折线图（当月趋势）
- 3 张统计卡片：总支出、本月支出、最高单笔
- 开销列表（倒序 + 类别筛选 + 删除）
- localStorage 持久化
- JSON 导出 / 导入 / 清空

### 6.2 Out of Scope for MVP
- 预算提醒（等核心流程跑通再考虑）
- 月收入记录（复杂度提升不大但当前无必要）
- CSV 导入微信/支付宝账单（格式解析复杂，作为 v2 加分项）
- 深色模式（可快速加但非核心）

## 7. Success Metrics

**Primary**
- **SM-1**: 核心流程可演示 —— 打开页面 → 录入 3 条数据 → 看到图表刷新，全程 < 30 秒，无报错。 Validates FR-1, FR-4, FR-7。

**Secondary**
- **SM-2**: 持久化可靠 —— 录入数据后刷新页面，数据 100% 保留。 Validates FR-10。
- **SM-3**: 构建通过 —— `npm run build` 成功或直接用浏览器打开 HTML 文件无控制台错误。

**Counter-metrics (do not optimize)**
- **SM-C1**: 不要为了"酷炫"加动画和过渡效果 —— 这会拖慢开发并增加 bug 面，不符合课程大作业的"够用就行"原则。

## 8. Open Questions

1. 是否需要支持编辑已录入的开销？（倾向：v1 不做，删除重录即可）
2. 自定义类别是否支持删除？（倾向：v1 不做，类别只增不减）
3. 无数据时的空状态，用什么视觉？（倾向：简单文字提示 + 一个图标）

## 9. Assumptions Index

1. 目标用户使用现代浏览器（Chrome/Edge/Firefox 最新版），ECharts 5.x 可正常运行。
2. localStorage 存储空间（通常 5MB）足够个人开销数据使用（一年上万条记录没问题）。
3. 用户理解"纯前端、数据不联网"的含义，不会因为担心云端丢失来找后端。
